# SQL aggregate placement and pagination study


Code, frozen protocol, SQL, raw measurements, query plans and analysis for a controlled experiment on how aggregate-query design interacts with OFFSET and known-cursor keyset pagination in a PostgreSQL-backed product-report API (PostgreSQL 17.2, Redis 7.4.2, Node.js).

The associated manuscript is unpublished. The Zenodo archive DOI is added with the first release.

## Contents

- `backend-study/PROTOCOL.md` — frozen protocol. `backend-study/manifest.json` — frozen randomized trial manifest (seed 20261021).
- `backend-study/sql/` — the six SQL templates (3 designs × OFFSET/keyset). `backend-study/src/` — API, preparation, correctness oracle and plan capture.
- `backend-study/results/raw/` — per-request timings, audit events, EXPLAIN JSON and environment record (SHA-256 hashes in `results/derived/raw-sha256.json`).
- `backend-study/results/derived/` — summaries, contrasts, drift and plan counters regenerated by `analyze.py`.
- `backend-study/extensions/` — four follow-up sensitivity experiments with their own protocol, frozen manifest (seed 20261022), code, raw results and analysis: cursor acquisition, an independently generated heavy-tailed dataset, default JIT/parallel settings and removed child indexes. See `backend-study/extensions/PROTOCOL.md`.
- `app/` — shared schema, backend and the base synthetic dataset.

## Reproduce

Analysis only (no Docker): Python 3.11+.

```sh
python3 -m venv .venv
.venv/bin/pip install -r results/requirements.txt
.venv/bin/python backend-study/analyze.py
```

A new guarded collection needs macOS, Docker Desktop and Node.js 22: `BACKEND_PYTHON="$PWD/.venv/bin/python" backend-study/reproduce` runs the collection and analysis. Timings depend on hardware; the published numbers come from one host, one session and one synthetic workload. They do not support general performance claims.

The follow-up experiments are reproduced with `python3 backend-study/extensions/run.py` and `python3 backend-study/extensions/analyze.py`.
